# Phase 2 — Define what "independent" means

Before changing code, write down an explicit experimental policy.

At minimum distinguish:

### A. Exact duplicate

Same:

```text
fixture_id
market_type
selection
```

This must never result in two separate experimental picks.

### B. Same-market duplicate

Example:

```text
Match A — 1X2 — Home
Match A — 1X2 — Home
```

Must be one observation.

### C. Mutually exclusive selections

Example:

```text
Match A — 1X2 — Home
Match A — 1X2 — Away
```

These are not independent observations.

### D. Overlapping selections

Example:

```text
Match A — Double Chance 1X
Match A — Double Chance X2
```

These are correlated/overlapping and must not be treated as independent evidence.

### E. Cross-market correlation

Examples:

```text
Match A — Home
Match A — Home + Over
Match A — Over 2.5
Match A — BTTS Yes
```

Determine which relationships the existing system explicitly models and which it does not.

Do not invent an arbitrary correlation matrix just to reduce pick volume.

The policy must be evidence-based and minimal.

# Phase 4 — Implement the minimum safe fix

If the audit confirms a real integrity problem:

Implement the **smallest deterministic fix**.

Preferred principles:

1. Normalize identity first.
2. Deduplicate before persistence.
3. Make duplicate prevention deterministic.
4. Keep the frozen model unchanged.
5. Keep the experiment's market coverage unchanged.
6. Preserve valid independent picks.
7. Do not silently discard picks without recording why.

If a pick is rejected because of correlation/duplication, record the reason somewhere auditable, for example:

```text

duplicate_market
correlated_selection
same_fixture_limit
```

Use the existing architecture where possible rather than introducing a large new subsystem.

# Phase 5 — Statistical correction if required

If the audit shows that multiple picks from the same fixture are still allowed and are legitimately correlated, determine whether the evaluation layer needs cluster-aware statistics.

Potential approaches include:

* cluster bootstrap by fixture;
* fixture-level aggregation;
* robust standard errors;
* permutation at fixture level.

Do not implement all of them automatically.

Choose the statistically appropriate method based on the actual structure of the data and explain why.

The goal is:

> A fixture with 3 correlated selections must not provide the same statistical evidence as 3 independent fixtures.

However, do not collapse genuinely different markets unnecessarily if the evidence supports treating them separately.
